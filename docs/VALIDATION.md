# Validation

Nothing in this table has been run on a real GA UK application. The tests use
ten invented applications, generated by `tests/make_fixtures.py` so that what
each one carries can be read in the source. The table gives the checker's
results. Separately from the table, a handful of people have run the tool over
real drafts of their own and reported back; several of the changes in
`CHANGELOG.md` came from those reports. Their applications were not collected
or kept, so nothing from them is measured here.
A review of the same fixtures finds plenty to criticise, as it should, because
their text is placeholder filler.

| Fixture | What it carries | Checker result |
|---|---|---|
| F001, F003 | clean Czech and English applications | no finding |
| F002 | a six-page proposal, a three-page CV, a budget over the ceiling and the wage cap, too small a stipend share, ineligible costs | five breaches (two page limits, three budget rules) and several advisories |
| F004 | three prescribed sections missing | one advisory naming them |
| F005 | Czech version of the form, English proposal | one advisory |
| F006 | a proposal with no text layer | UNKNOWN, never a breach; the page count is still checked |
| F007 | English version of the form, Czech proposal | one advisory |
| F008 | a Word draft of the proposal, which the checker reads and asks to have converted to PDF, an ethics committee statement, a leader's CV with exactly ten publications, supervisor pay above the 10 % recommendation, respondents paid as a service, a conference with a poster | no finding |
| F009 | a timetable in academic years that names 2026 and 2028 | one advisory |
| F010 | a leader's CV with twelve publications | one advisory |

The test suite asserts the no-finding cases first. A finding against an
application that is in order sends a student after a problem that does not
exist, days before a deadline, and that is the failure the tool most needs to
avoid. The suite also covers input a student might really give: amounts
written as "160 000 Kč" or "160000.0", a file name that fits two attachments,
two candidate proposals, a Word draft with deleted tracked changes, a broken
`form.yml`. It checks that the quote verifier catches an invented quote, a
quote whose ellipsed pieces are out of order and a quote too short to place;
that the generated prompts match their sources; and that no personal path or
email address has entered a published file. It runs on every push.

What the tests cannot show is whether the tool helps. That needs real
applications and the judgement of the students who wrote them and the
supervisors who read them. The next step is a small retrospective: with the
authors' consent, run the check on applications that had to be corrected, and
count how many of the real problems it finds and how many it invents. If you used the tool, a short issue saying whether a
finding helped, or was wrong, is the most useful thing you can send. Describe
the finding; do not paste your text.
